# 下一阶段：完成 LLM 与数据库能力

制定日期：2026-10-23。本文承接当前代码，作为近期执行清单；长期路线仍见 `design/07-V1-实施计划.md`。
本阶段由作者亲手实现核心逻辑，Agent 协助解释、审查与排错。下面的文件名和方法名是推荐设计，尚未实现。

## 1. 阶段目标与范围

完成后应达到：给定请求，LLM 能返回文本或完成工具交互；给定会话数据，store 能可靠保存并读回；两者各自有离线测试。

| 本阶段交付 | 后续阶段推进 |
|---|---|
| 一种真实模型协议、fake、工具调用循环 | 其余模型协议、流式输出、更多业务工具 |
| SQLite 版本迁移、会话/轮次/模型请求记录读写 | MySQL、运维查询与清理 |
| 模块测试、一次真实模型调用验证 | chat.Service、历史组装、会话队列、分段回复、QQ 全链路 |

优先实现 `openai-chat` 分支，与现有示例配置的方向一致；若实际使用其他协议，可替换该任务。
HTTP 字段与工具消息映射在编码时查所选服务的官方文档确认。
本阶段的“接入”指工厂可创建真实模型、数据库接口可调用；主程序正式替换 echoLoop 属于下一阶段。

## 2. 开发顺序与验收

### A1 · 收尾工具注册中心与调用循环

- [ ] 在 `internal/llm/tools/registry.go` 提供初始化方式，修复 nil map 写入；拒绝 nil handler、空名称和重复注册。
- [ ] 修复 `engine.go` 中 `fmt.Sprintf` 的 `%w` 用法；明确没有 registry 却收到工具调用时返回错误的行为。
- [ ] 检查 context 取消：每轮请求与每次工具执行前检查，并将同一 ctx 向下传递。
- [ ] 明确 `maxSteps` 表示模型调用次数上限；工具执行失败作为结果交给模型，模型调用失败则返回错误。
- [ ] 用脚本式 fake 验证两次请求：第一次返回工具调用，第二次检查调用 ID、参数、结果和消息顺序，再返回最终回答。

验收：普通回答、成功工具交互、未知工具、工具执行失败、超限、取消均有确定结果；多工具响应不会丢失结果。
学习重点：map 零值、构造函数、接口替身、锁范围、context 传递。

### A2 · 实现一种真实模型适配器

- [ ] 新增 `internal/llm/provider/openaichat/`，以标准库 `net/http` 实现 `llm.Client`，接入现有工厂。
- [ ] 支持现有配置中的地址、凭据、模型、输出长度、温度与超时；明确 base_url 的路径拼接规则。
- [ ] 转换文本、工具定义、assistant 工具调用与工具结果；解析回答、调用参数、停止原因和 Token 消耗。
- [ ] 用 `httptest.Server` 检查请求内容及响应解析，不依赖真实 QQ 或真实模型。

验收：文本和工具调用能往返转换；响应体可靠关闭；取消能中断 HTTP 请求；fake 分支继续可用。
学习重点：JSON DTO、HTTP 生命周期、依赖注入、中性模型与协议模型的区别。

### A3 · 错误、重试与配置收尾

- [ ] 映射已有 `llm.ErrAuth`、`ErrRateLimited`、`ErrRetryable`、`ErrContextTooLong`，保留底层错误链。
- [ ] 处理非成功 HTTP 响应、非法 JSON、缺失有效输出；上下文超长的识别以实际协议为准。
- [ ] 明确 `max_attempts` 包含首次请求，仅一个位置负责重试；鉴权错误不重试，等待退避时监听取消。
- [ ] 校验真实模型必填配置、正数超时和有效尝试次数；同步 `config.yaml.example`。
- [ ] 修复示例配置 `database.driver` 后说明缺少 `#` 的 YAML 问题，验证示例可解析。
- [ ] 日志及错误信息不泄露 API Key；原始响应快照也需排除凭据。

验收：本地 HTTP 测试覆盖鉴权、限流、服务错误、超时、取消与畸形响应，断言重试次数和 `errors.Is`。
随后手动做一次真实文本调用；工具能力可用时再验证一次工具交互，记录结果，真实调用不进入自动测试。

### B1 · 完成版本化数据库迁移

- [ ] 新增 `internal/store/migrate.go`，嵌入迁移文件，按版本排序并使用 `PRAGMA user_version`。
- [ ] 每个迁移的 SQL 和版本更新放进同一事务；失败回滚，数据库版本高于程序支持版本时拒绝继续。
- [ ] 明确 `Open`、`InitSchema` 与迁移的关系，保留一个清晰入口，停止每次启动直接重复执行建表 SQL。
- [ ] 替换现有 `test_table` 练习测试，验证真实业务表、外键、重复迁移及重新打开数据库。
- [ ] 检查本地是否存在“已建表但版本为 0”的旧库；开发空库可手动换新路径，有数据的库需先制定兼容方案。

验收：新库能初始化，重复运行和重新打开均成功；失败迁移不留下部分表或错误版本。
学习重点：embed、sql.Tx、迁移版本与事务原子性。迁移文件发布后只追加。

### B2 · 用户与会话读写

- [ ] 在 store 内实现获取或创建用户（app_id + openid）及会话（app_id + scene + scene_id）。
- [ ] 使用数据库唯一约束保证身份唯一，不依赖进程内“先查后写”来防重。
- [ ] 对外返回领域数据，内部封装 SQL；业务调用方不通过 `DB()` 执行 SQL。

验收：重复调用返回相同 ID，不同 AppID 或场景相互隔离；真实数据重开数据库后仍可读取。
学习重点：唯一约束、UPSERT、参数化 SQL。群资料管理暂不扩展。

### B3 · 轮次生命周期与历史查询

- [ ] `BeginTurn`：事务内创建 processing 轮次和首条用户消息；重复消息返回原轮次及状态。
- [ ] 区分重复的已完成轮次和未完成轮次；store 返回事实，是否重试由后续 chat 决策。
- [ ] `FinishTurn`：事务内保存回复消息及终态，成功/失败/过滤都能记录；重复结束不重复插入。
- [ ] `RecentTurns`：按会话取最近 N 个成功轮次，再按从旧到新返回；轮内消息按序排列。
- [ ] 约定 N <= 0 返回空结果；数据库时间存 Unix 毫秒，可空字段正确处理。

验收：重复入站只建一轮；事务失败不留半轮；失败和处理中轮次不进入历史；超过 N 轮时裁剪与顺序正确。
学习重点：事务边界、状态转换、幂等、sql.Null* 或指针、rows.Close/rows.Err。

### B4 · 模型请求记录与工具消息持久化

- [ ] 实现 `RecordLLMRequest`，保存请求/响应快照、模型、耗时、Token、错误和 trace_id。
- [ ] 明确快照含义：中性 Request/Response 的 JSON 不等于供应商原始 HTTP JSON；按现有全量快照设计，先确定适配器向外提供记录的方式。
- [ ] 明确关联方式：一轮可有多次模型调用，现有 turns.llm_request_id 只能指向一条。推荐增加可空 llm_requests.turn_id，轮次保留最后一次调用引用；若采用此方案，追加迁移并同步领域类型。
- [ ] 明确工具历史编码：现有 messages.content 只存字符串，须约定结构化 JSON 格式，能还原调用 ID、参数和工具结果。
- [ ] 对可能发起多次请求的重试与工具循环，区分每次调用的 Token 和整轮总量，避免只保存最后一次响应导致记录遗漏。

验收：成功和失败均可追溯；同一轮多次调用不丢记录；工具消息序列写入后能完整读回。
以上记录接口和表结构属于本阶段设计点，动手前先画数据流并确认方案；不把 store 直接塞进协议适配器。

### C · 模块联合验收

- [ ] 用测试把 store、fake 模型、工具引擎串成一次问答，显式创建依赖，SQL 仍封装在 store。
- [ ] 验证同一会话两轮问答：第一轮保存后，第二轮能读取其历史；关闭并重新打开数据库再验证。
- [ ] 验证失败调用留记录但不进入成功历史，工具调用记录与消息能还原。
- [ ] 更新进度文档，分别记录离线测试和真实模型验证结果。

此测试只是模块协作验证；消息订阅、历史 Prompt 编排和 QQ 回复仍由下一阶段 chat.Service 实现。

## 3. 推荐安排

按学习单元安排，不按日历强推；每单元建议 1–2 小时，遇到不熟悉的机制可以拆开。

| 单元 | 任务 | 建议完成时提交 |
|---|---|---|
| 1–2 | A1 工具模块收尾与测试 | 工具循环可独立验证 |
| 3–5 | A2–A3 真实模型、错误与配置 | 一种协议可用且错误行为明确 |
| 6–7 | B1 迁移与存储测试 | 数据库可重复启动 |
| 8 | B2 用户与会话 | 身份唯一且持久化 |
| 9–10 | B3 轮次与历史 | 数据层支持完整问答生命周期 |
| 11–12 | B4、C 记录设计与联合验证 | 本阶段验收通过 |

每个单元采用“先说清输入输出和错误 → 手写实现 → 验证 → 回顾并提交”的节奏。
估计约 12–24 小时，仅作拆分参考；协议调试、快照设计和迁移兼容可能需要额外时间。
