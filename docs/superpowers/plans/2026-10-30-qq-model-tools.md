# QQ 对话与跨语言工具接入

目标：在当前 feature/llm-layer 分支，将已有 QQ 私聊、OpenAI Chat 适配器、Python 位置和 Node 天气工具接成可运行链路。

## 范围与选择

- 保留已有修改；直接在当前分支实现，不另建分支。实现后作者已要求按功能分阶段本地提交，不推送。
- main 仅组合依赖；chat.Service 负责接收入站、会话分片串行化、内存历史、去重、调用引擎和分段回复。
- 同会话有序，不同分片可并行；取消向队列、HTTP、脚本和回复传递。
- 使用现有配置体系，新增 tools.directory 与 tools.max_steps；目录相对配置文件定位。
- 启动时加载工具并注册到 Registry，再创建 Engine。暂不增加热重载、斜杠命令或数据库存储。
- 错误记录在日志，QQ 返回简短失败提示；输出按 rune 分段并遵守配置的回复次数上限。
- 真实模型测试显式选择运行，普通测试使用本地 HTTP 服务与真实 Python/Node 脚本。

## 执行顺序

1. 写工具回归测试，复现 YAML 映射丢失；修复加载、锁、注册初始化、脚本取消与错误输出。
2. 写配置/工厂测试，接通 openai-chat，校验时长、模型与凭据，定位 skills 目录。
3. 写 Service 测试和本地 HTTP 端到端测试，验证位置→天气→最终回答、历史隔离、去重、错误回复及退出。
4. 实现 Service 与分片队列；main 替换 echoLoop 并保证资源清理。
5. 补充启动说明与脚本单测；执行格式、构建、vet、race、Python/Node 测试；请求独立代码审查。
6. 模型配置就绪后编译启动 QQ 进程并核对连接日志；实际收到 QQ 消息及工具调用后再记录真机验收。

## 验证重点

- 工具结果的 call_id 必须与 assistant 发出的工具调用对应，多轮 HTTP 请求保留调用顺序。
- 同会话连续两条消息不能乱序；不同会话历史不串线；平台重复事件不重复请求模型。
- 超时不泄漏子进程；失败不能阻塞下一条消息；停机释放平台。
- QQ 分段共用同一个 ReplyRef，中文不按字节切分。
- 不将模型密钥、完整模型错误或配置内容回传给 QQ 或打印到日志。
