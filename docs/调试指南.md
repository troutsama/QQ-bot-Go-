# VS Code 调试

用 VS Code 打开仓库根目录。使用 WSL 时，左下角应显示 WSL，Go 扩展和 Delve 都安装在 WSL 中。

## 工具准备

项目固定使用 Go 1.23.6。Delve 固定安装 v1.24.2，避免自动安装新版工具提高 Go 版本要求：

```bash
go version
GOTOOLCHAIN=local go install github.com/go-delve/delve/cmd/dlv@v1.24.2
"$(go env GOPATH)/bin/dlv" version
```

VS Code 的 Go 扩展会在 GOPATH/bin 查找 dlv，因此终端 PATH 中没有 dlv 不影响此查找。
如果扩展仍报告找不到工具，运行命令 `Developer: Reload Window` 后重试。

## 跟踪模型请求（推荐先走这一条）

1. 打开 `internal/llm/provider/openaichat/client_test.go`，在 `client.Complete(...)` 那一行左侧点击设置断点。
2. 打开 `client.go`，在 `Complete`、`tochatRequest` 和 `toResponse` 内设置断点。
3. 打开“运行和调试”（Ctrl+Shift+D），选择“模型调用：调试 TestComplete（本地模拟服务）”，按 F5。
4. 配置会先停在入口；按 F5 继续到断点。F10 单步跳过，F11 进入函数，Shift+F11 跳出。
5. 在“变量”或“监视”中查看 `req`、`data`、`httpReq`、`resp.StatusCode`、`body`、`got`。编码后可以监视 `string(data)`。

调用路径：`TestComplete → New → Complete → tochatRequest → HTTP 模拟服务 → toResponse → 测试断言`。
模拟服务的 handler 在另一个 goroutine 中运行；想查看它收到的请求，应在 handler 内另设断点。
调试启动时关闭单测超时，避免暂停在断点期间测试超时。

也可以点击测试函数上方的 `debug test`，或在“测试”面板中对单个测试选择调试。
“单测：调试当前文件所在包”适用于当前打开的 Go 文件；它会运行该包内的全部测试。

## 跟踪主程序

选择“主程序：mock + fake（启动流程）”，按 F5。此配置使用 `.vscode/config.debug.yaml`，日志写入 `data/logs/debug.log`。
建议断点：`main → run → config.Load → cfg.Validate → 两个 factory.New → provider.Start → echoLoop`。

当前主程序只创建模型客户端，业务循环仍是回显，尚未调用 `Complete`；LLM 工厂中的 `openai-chat` 分支也尚未接入。
mock 平台不会自动产生入站消息，所以运行到 `echoLoop` 的 select 后等待属于正常行为。
要跟踪模型转换与 HTTP 请求，使用上面的 TestComplete 配置。

“主程序：使用本机 config.yaml”读取你原有配置，可能连接 QQ。它不会替你修正配置或实现尚未接入的工厂分支。

## 常见问题

- 断点呈灰色：确认启动的是包含该代码的包；模型单测与主程序是两条不同执行路径。
- 提示找不到 main：从仓库根目录打开项目并选择对应的启动项，避免对非 main 文件直接运行。
- 找不到配置或日志路径错误：启动项已经固定 cwd 为仓库根目录，并显式指定配置路径。
- 真服务调试超时：HTTP 客户端自己的 Timeout 仍然有效；先使用本地模拟服务梳理流程。
- Go 版本不兼容：检查 `go version` 和 `dlv version`，保持 `GOTOOLCHAIN=local`，不要用关闭 Delve 版本检查掩盖问题。
