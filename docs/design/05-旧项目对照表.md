## 7.6 不能一对一翻译的 7 个语义差异（⚠️ 迁移时的红灯）

| # | OneBot 11 / NapCat | QQ 官方 Bot | 影响 |
|---|--------------------|-------------|------|
| 1 | 直接用 QQ 号做用户标识 | **openid，且 per-AppID 变化**；私聊 `user_openid` 与群里 `member_openid` 是两套 | 所有表的键 |
| 2 | 想发就发（无窗口限制） | **被动回复有窗口与次数上限**（单聊 60min/4 次；群聊 5min/5 次），主动消息有频控 | 分段发送、cron、错误提示都受影响 |
| 3 | 消息 ID 由自己管，无去重语义 | **同一 `msg_id` 会重复推送**；`msg_seq` 重复会被平台去重（`40054005`） | 幂等 + 序号管理为必需 |
| 4 | 有好友申请事件 | **无好友申请概念** | `friend-request` 模块整体删除 |
| 5 | 群消息无 @ 前缀处理 | 群事件 `content` 已自动剥离 @ 前缀 | 群聊解析（以后） |
| 6 | 语音/图片都是「消息段」，直接发 | 富媒体需**先上传拿 `file_info`** 再发送，且有有效期 | 语音取消；将来做图片时是两阶段流程 |
| 7 | 长连接是唯一接收方式 | WS 将下线，**webhook 是新链路**（HTTPS + 签名验签） | `Provider` 端口必须留 `WebhookReceiver`（R22） |

## 7.8 迁移时的建议顺序（避免来回翻文件）

1. 先读 `07`（本文件）确定每块代码的归属迭代
2. 再读 `03`（接口）→ 写 `platform` 端口 + `llm` 端口 + mock 实现
3. 再读 `04`（表结构）→ 写 `store` + 迁移
4. 再读 `05`（配置/API）→ 写 `config` + `logx` + `admin`
5. 最后写 `chat`（编排），此时代理都齐了，可以只靠 mock 跑通
6. 最后接真实 `qqbot` 适配器 + botgo

**不要**先写 `qqbot` 适配器 —— 那会让你在没有 mock 的情况下被迫用真实 QQ 调试，效率极低。
