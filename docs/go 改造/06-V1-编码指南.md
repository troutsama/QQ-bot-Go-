## 9.1 V1 开发顺序：先让「假的一切」跑通，再逐个换成真的

这是本指南最重要的建议。**不要从 `qqbot` 适配器开始写** —— 那样你每改一行都要连真实 QQ 验证，反馈周期是分钟级，而且一条消息只能测一次（被动回复次数有限！）。

正确顺序是**两阶段**：

### 阶段 A：走通的骨架（全部用假实现，8 步，每步都能运行）

| 步 | 产出 | 完成标志 | 自测 |
|----|------|----------|------|
| A1 | `go mod init` + 目录骨架 + `Makefile` | `go build ./...` 通过 | `make build` |
| A2 | `internal/version` + `cmd/botd/main.go`（只打印版本） | 进程能起、能响应 Ctrl-C | `go run ./cmd/botd` |
| A3 | `internal/logx` | 日志同时进控制台和文件，带轮转 | 看 `data/logs/botd.log` |
| A4 | `internal/config` | 能读 `config.yaml`、`${VAR}` 替换、校验失败会退出 | 故意写错 YAML 看报错 |
| A5 | `internal/store` + `0001_init.sql` | 启动后 `data/bot.db` 生成，4 张表存在 | `sqlite3 data/bot.db .schema` |
| A6 | `internal/platform`（port + **mock**） | mock provider 能注入事件 | 单测 |
| A7 | `internal/llm`（port + **fake**） | fake client 固定返回一句话 | 单测 |
| A8 | `internal/chat`（含 outbound/pipeline/service）+ `internal/admin` | **`/admin/debug/inject` 能走完整链路，回复被打印出来** | curl 一次 |

**A8 完成时你就已经有一个「不依赖 QQ 也能完整运行」的系统了。** 这是最关键的里程碑：之后所有逻辑（上下文、分段、幂等、错误处理）都可以用 curl 反复测。

### 阶段 B：逐个换成真实实现（5 步）

| 步 | 产出 | 完成标志 |
|----|------|----------|
| B1 | `llm/provider/openaichat` | `llm.protocol: openai-chat` 时能真的调用模型 |
| B2 | `llm/provider/anthropic`、`llm/provider/openairesponses` | 三个协议都能用（R7：**必须 V1 写完**） |
| B3 | `platform/provider/qqbot` 的 `inbound.go` | 真实消息能进来（先只打日志，不回） |
| B4 | `platform/provider/qqbot` 的 `outbound.go` + `replyseq.go` | 能真实回复（含分段与序号） |
| B5 | `platform/provider/qqbot` 的 `logger.go` + 重连 | botgo 日志接进 `logx`；断网重连只处理一次 |

### 每步都遵守一个循环

```
写接口 → 写假实现 → 写单测 → 让上层跑通 → 再写真实现
```

这就是「端口/适配器」在个人项目里的真正价值：**你永远有一半是假的，所以永远测得起。**

## 9.2 Go 新手须知（对照 TS / Java 的习惯差异）

### 先建好工程习惯（开工前 5 分钟）

```bash
go mod init qqbot          # 生成 go.mod（相当于 package.json）
go get modernc.org/sqlite  # 加依赖
go build ./...             # 编译全部
go vet ./...               # 静态检查（比 TS 的 lint 更聚焦真问题）
gofmt -l -w .              # 格式化：Go 不允许风格争论
go test ./... -race        # 跑测试 + 竞态检测（免费的数据竞争检测器，务必常用）
```

### 16 个必须提前知道的点

| # | 主题 | 要点 | 常见踩坑 |
|---|------|------|----------|
| 1 | **可见性靠大小写** | `Foo` 导出（包外可见），`foo` 包内可见。没有 `public`/`private`，没有 `export` | 想给别的包用却小写首字母 → 编译错 `undefined` |
| 2 | **一个目录 = 一个包** | 目录名不必等于包名，但惯例一致（`internal/store` → `package store`） | 把两个包放同一目录 → 编译错 |
| 3 | **interface 是隐式实现** | 不需要 `implements`。只要方法集匹配就自动满足 | 想「在这个类型上声明它实现了某接口」→ Go 里没有这种语法；用 `var _ platform.Provider = (*qqbot.Provider)(nil)` 做编译期断言 |
| 4 | **接口定义在使用方** | `chat` 包声明它需要什么接口，`store` 包不需要导出接口。这是 Go 与 Java 最大的习惯差异 | 在 `store` 包里定义 `Store` 接口 → 造成 `store` 与 `chat` 互相依赖 |
| 5 | **error 是值，不是异常** | 立即处理：`if err != nil { return fmt.Errorf("读配置: %w", err) }`。用 `%w` 包装才能被 `errors.Is/As` 解开 | 用 `panic` 处理业务错误；或者 `err.Error()` 字符串比较（应该用哨兵错误 + `errors.Is`） |
| 6 | **哨兵错误** | `var ErrAuth = errors.New("llm: 鉴权失败")`，上层 `errors.Is(err, llm.ErrAuth)` | 用错误**文本**判断类型 → 改文案就坏 |
| 7 | **值接收者 vs 指针接收者** | 需要修改状态、含 `sync.Mutex`/`atomic` 的必须用指针接收者 `func (s *Service)` | 混用导致 mutex 被复制（`go vet` 会抓 copylocks） |
| 8 | **defer 陷阱** | 参数在 `defer` 语句执行时求值；`defer` 在**所在函数**返回时执行，不是代码块结束时 | 在循环里 `defer f.Close()` → 文件句柄堆积到函数结束 |
| 9 | **nil interface 陷阱** | `var e error = (*MyErr)(nil)` 时 `e != nil` 为 **true**（有类型没值） | 函数里 `return (*MyErr)(nil)` 冒充 `error` → 调用方 `err != nil` 成立却崩在解引用 |
| 10 | **channel 的所有权** | 只有发送方关闭 channel；关闭后再读返回零值而不是 panic；对已关闭 channel 发送会 panic | 多个 goroutine 都 `close` → panic |
| 11 | **map 并发读写会直接崩进程** | `fatal error: concurrent map read and map write` **不能被 recover** | 用 map 做缓存/去重却在多个 goroutine 里读写 → 必须加 `sync.Mutex` 或改用 `sync.Map` |
| 12 | **slice 共享底层数组** | `append` 返回新 slice，必须接收：`s = append(s, x)`。截取 `s[1:]` 与原 slice 共享内存 | 忘了接返回值 → 数据「丢」了；跨 goroutine 共享同一底层数组 → 数据竞争 |
| 13 | **context 用于传递取消与超时** | 一路透传 `ctx context.Context` 作为第一个参数 | 把 `context.Background()` 到处新建 → 超时/取消传不下去（关闭服务时卡死） |
| 14 | **time 相关** | `time.Duration` 是 int64 纳秒，`5 * time.Second`；`time.Time` 的比较用 `.Before/.After/.Equal`；**不要用 `==` 比时间**（含单调时钟与位置） | 用 `time.Local` 依赖机器时区 → 部署到 UTC 机器出错（R20） |
| 15 | **`go:embed`** | `//go:embed migrations/*.sql` + `embed.FS`，把 SQL 编进二进制 | 路径写错 → 编译期就报错（比运行时好） |
| 16 | **测试** | 表驱动 + `t.Run`；`t.TempDir()` 建临时目录；`httptest.NewServer` 假 HTTP；`t.Parallel()` 并行 | 测试之间共享全局状态 → 并行时互相干扰（这也是本项目「不许全局单例」的原因） |

### 三个最容易写错的地方（配代码）

**① nil interface**

```go
// ✗ 错误示范：看起来返回了 nil，实际不是
func getErr() error {
    var e *MyErr          // e == nil
    return e              // 转成 error 接口后，「类型=*MyErr，值=nil」→ 不等于 nil！
}
if err := getErr(); err != nil {
    fmt.Println(err)      // 打印 "<nil>"，但判断成立 → 逻辑错乱
}

// ✓ 正确：直接返回 nil
func getErr() error {
    var e *MyErr
    if e == nil {
        return nil
    }
    return e
}
```

**② channel 与关闭**

```go
// 生产者负责关闭；消费者只读
func (p *Provider) Start(ctx context.Context) error {
    go func() {
        defer close(p.events)          // 只有这一个 goroutine 关闭它
        for {
            select {
            case <-ctx.Done():
                return
            case ev, ok := <-raw:
                if !ok {
                    return             // 上游关闭
                }
                p.events <- translate(ev)  // 若消费者已退出，这里会永久阻塞 → 见下
            }
        }
    }()
    return nil
}
```

> 上面的 `p.events <- ...` 在消费者退出后会永久阻塞（goroutine 泄漏）。正确写法：
> ```go
> select {
> case p.events <- translate(ev):
> case <-ctx.Done():
>     return
> }
> ```
> **规则：任何「向 channel 发送」的地方都要配一个 `case <-ctx.Done()`。**

**③ slice 与循环变量**

```go
// ✗ 常见错误：defer 在循环里
for _, f := range files {
    fh, _ := os.Open(f)
    defer fh.Close()          // 全部堆到函数返回时才关
}

// ✓ 抽成函数，或显式关闭
for _, f := range files {
    func() {
        fh, _ := os.Open(f)
        defer fh.Close()
        _ = fh
    }()
}
```

### 9.3.2 `internal/logx`（半天）

**目标**：`logx.Setup(cfg) (*slog.Logger, error)`，把 `log/slog` 配成「文件 + 控制台双写 + 轮转」。

```go
package logx

import (
    "context"
    "io"
    "log/slog"
    "os"

    "gopkg.in/natefinch/lumberjack.v2"
)

// Setup 初始化根 logger。返回的 logger 已带 service 字段。
func Setup(cfg Config) (*slog.Logger, func() error, error) {
    if err := os.MkdirAll(cfg.Dir(), 0o755); err != nil {
        return nil, nil, err
    }

    rotator := &lumberjack.Logger{
        Filename:   cfg.File,
        MaxSize:    cfg.MaxSizeMB,   // MB
        MaxAge:     cfg.MaxAgeDays,  // 天
        LocalTime:  true,
        Compress:   true,
    }

    // 双写：控制台 + 文件
    w := io.MultiWriter(os.Stdout, rotator)

    level := new(slog.LevelVar)      // 支持运行时改级别（热重载用）
    level.Set(cfg.Level)

    h := slog.NewTextHandler(w, &slog.HandlerOptions{Level: level})
    logger := slog.New(h).With("service", "botd")

    return logger, func() error { level.Set(slog.LevelDebug); return rotator.Close() }, nil
}
```

**要点**

| 点 | 说明 |
|----|------|
| `slog.LevelVar` | 热重载日志级别时直接 `Set()`，不用重建 logger（§5.2 的「立即热载」档） |
| 返回值里那个 `func() error` | 关闭函数。Go 没有析构函数，**必须显式返回并 defer 调用**，否则轮转文件句柄不释放 |
| `Redact` | 再加一个 `func Redact(s string) string`，对已知密钥片段做替换。**所有打印请求头的地方都要过它**（R9） |
| trace_id | 不要塞进 context 值再到处取（反模式）。做法：在 `chat` 里生成后，用 `logger.With("trace_id", id)` 派生一个子 logger 往下传 |

**自测**：`go run` 后看 `data/logs/botd.log` 有内容，且 `ls data/logs/` 出现文件。

**三个关键实现点**

```go
// ① ${VAR} 占位符替换 + env 覆盖，在解析 YAML 之前做
func expandEnv(raw []byte) ([]byte, error) {
    // 支持 ${VAR} 和 ${VAR:-默认值}
    // 变量未定义且无默认值 → 返回错误（绝不静默用空值启动）
    return os.Expand(raw, func(key string) string {
        if v, ok := lookupWithDefault(key); ok {
            return v
        }
        return "" // 但要另外收集「缺失变量」并报错
    }), nil
}

// ② Validate：启动与 reload 都要调
func (c *Config) Validate() error {
    var errs []error
    if c.Server.AdminToken == "" {
        errs = append(errs, errors.New("server.admin_token 不能为空"))
    }
    switch c.Bot.Provider {
    case "qqbot", "mock":
    default:
        errs = append(errs, fmt.Errorf("bot.provider 未知: %q", c.Bot.Provider))
    }
    switch c.LLM.Protocol {
    case "openai-chat", "openai-responses", "anthropic", "fake":
    default:
        errs = append(errs, fmt.Errorf("llm.protocol 未知: %q", c.LLM.Protocol))
    }
    if c.Chat.MaxReplySegments < 1 || c.Chat.MaxReplySegments > 4 {
        errs = append(errs, fmt.Errorf("chat.max_reply_segments 必须在 1..4（被动回复上限）"))
    }
    return errors.Join(errs...)   // Go 1.20+：把多个错误合成一个
}
```

**③ 热重载的核心类型：`atomic.Pointer` 快照**

```go
// 不要用「一把大锁保护整个 Config」的写法。
// 读多写少的配置，用原子指针换整个快照，读者完全无锁：
type Holder struct {
    p atomic.Pointer[Config]
}

func (h *Holder) Load() *Config      { return h.p.Load() }
func (h *Holder) Store(c *Config)    { h.p.Store(c) }
```

`chat.Service` 收到的 `Cfg func() ChatConfig`（§3.4.1）就是这个 Holder 的一层包装：

```go
cfgFn := func() config.ChatConfig { return holder.Load().Chat }
```

**Diff / ChangeSet：三档分类**

```go
type Level int
const (
    LevelHot     Level = iota // 立即热载
    LevelReconnect            // 需重连
    LevelRestart              // 必须重启进程
)

type ChangeSet struct {
    Hot       []string
    Reconnect []string
    Restart   []string
}

func (cs ChangeSet) NeedsRestart() bool { return len(cs.Restart) > 0 }
```

**新手提示**：`Diff` 最土的写法就是逐个字段 `if old.X != new.X { cs.Hot = append(...) }`。**就这么写**，别想着反射。字段只有 30 来个，手写反而清楚，也方便加注释说明每项归哪档。

**自测（表驱动单测）**

```go
func TestDiff(t *testing.T) {
    tests := []struct {
        name    string
        mutate  func(*Config)
        wantHot []string
        wantRst []string
    }{
        {"改模型", func(c *Config) { c.LLM.Model = "x" }, []string{"llm.model"}, nil},
        {"改端口", func(c *Config) { c.Server.Listen = "0.0.0.0:9" }, nil, []string{"server.listen"}},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            old := defaultConfig()
            next := *old
            tt.mutate(&next)
            cs := Diff(old, &next)
            if !slices.Equal(cs.Hot, tt.wantHot) { t.Errorf("hot = %v, want %v", cs.Hot, tt.wantHot) }
            if !slices.Equal(cs.Restart, tt.wantRst) { t.Errorf("restart = %v", cs.Restart) }
        })
    }
}
```

### 9.3.4 `internal/store`（1.5 天）

**目标**：`Open(path) (*Store, error)` + `Migrate(ctx)` + 各聚合的查询方法。

```go
package store

type Store struct{ db *sql.DB }

func Open(path string) (*Store, error) {
    // ① DSN 里带 PRAGMA（不要用 Exec，见 §4.6）
    dsn := "file:" + path +
        "?_pragma=journal_mode(WAL)" +
        "&_pragma=busy_timeout(5000)" +
        "&_pragma=foreign_keys(1)" +
        "&_pragma=synchronous(NORMAL)"

    db, err := sql.Open("sqlite", dsn)     // driver 名固定为 "sqlite"（modernc）
    if err != nil {
        return nil, fmt.Errorf("打开数据库: %w", err)
    }
    db.SetMaxOpenConns(1)                   // V1 的选择，见 §4.6
    db.SetMaxIdleConns(1)

    if err := db.Ping(); err != nil {       // sql.Open 不会真的连接，Ping 才会
        return nil, fmt.Errorf("连接数据库: %w", err)
    }
    return &Store{db: db}, nil
}

func (s *Store) Close() error { return s.db.Close() }
```

> **新手必踩**：`sql.Open` 不连接数据库，只校验参数，所以路径写错时不会报错。**一定要 `Ping()`**。

**迁移（`//go:embed` + `user_version`）**

```go
package store

import (
    "context"
    "embed"
    "fmt"
    "sort"
)

//go:embed migrations/*.sql
var migrationFS embed.FS

func (s *Store) Migrate(ctx context.Context) error {
    var current int
    if err := s.db.QueryRowContext(ctx, "PRAGMA user_version").Scan(&current); err != nil {
        return fmt.Errorf("读取 user_version: %w", err)
    }

    files, err := migrationFiles()          // 返回 []migration{version, name, sql}
    if err != nil {
        return err
    }

    for _, m := range files {
        if m.version <= current {
            continue
        }
        if err := s.applyOne(ctx, m); err != nil {
            return fmt.Errorf("迁移 %s 失败: %w", m.name, err)
        }
    }
    return nil
}

func (s *Store) applyOne(ctx context.Context, m migration) error {
    tx, err := s.db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()                      // 成功时 Commit 后 Rollback 是 no-op，是惯用写法

    if _, err := tx.ExecContext(ctx, m.sql); err != nil {
        return err
    }
    // ⚠️ user_version 不能用占位符参数（PRAGMA 不支持），必须拼字符串
    if _, err := tx.ExecContext(ctx, fmt.Sprintf("PRAGMA user_version = %d", m.version)); err != nil {
        return err
    }
    return tx.Commit()
}
```

**三个坑**

| 坑 | 说明 |
|----|------|
| `PRAGMA user_version = ?` 不支持参数 | 只能 `fmt.Sprintf` 拼（version 是我们自己控制的整数，无注入风险） |
| `defer tx.Rollback()` 的惯用法 | Commit 成功后再 Rollback 会返回 `ErrTxDone`，**直接忽略即可**，不要写成 `if err := tx.Rollback(); err != nil { return err }` |
| 迁移在事务里 | SQLite 的 DDL 支持事务，这点比 MySQL 好 |

**查询方法（以 `turns` 为例）**

```go
// BeginTurn 返回 TurnRef，IsNew=false 表示幂等命中（§3.4.3）
func (s *Store) BeginTurn(ctx context.Context, p chat.TurnParams) (chat.TurnRef, error) {
    now := p.StartedAt.UnixMilli()

    res, err := s.db.ExecContext(ctx, `
        INSERT INTO turns (conversation_id, inbound_msg_id, sender_openid, sender_nickname,
                           status, trace_id, started_at)
        VALUES (?, ?, ?, ?, 'processing', ?, ?)
        ON CONFLICT (conversation_id, inbound_msg_id) DO NOTHING
    `, p.ConvID, p.MsgID, p.Sender.OpenID, p.Sender.Nickname, p.TraceID, now)
    if err != nil {
        return chat.TurnRef{}, fmt.Errorf("插入轮次: %w", err)
    }

    n, err := res.RowsAffected()
    if err != nil {
        return chat.TurnRef{}, err
    }
    if n == 1 {
        id, _ := res.LastInsertId()
        // 同时写入第一条 user 消息
        if _, err := s.db.ExecContext(ctx, `
            INSERT INTO messages (turn_id, seq_in_turn, role, content, created_at)
            VALUES (?, 0, 'user', ?, ?)`, id, p.UserText, now); err != nil {
            return chat.TurnRef{}, fmt.Errorf("写入 user 消息: %w", err)
        }
        return chat.TurnRef{ID: id, IsNew: true, Status: chat.StatusProcessing,
            StartedAt: p.StartedAt}, nil
    }

    // 冲突：读回既有轮
    return s.loadTurnRef(ctx, p.ConvID, p.MsgID)
}
```

> **注意**：这里为了简单，两条 INSERT 没有放在同一事务里。**实际实现应该包一层事务** —— 你自己补上（这是练习点：用 `BeginTx` 包住 `BeginTurn` 的两条插入）。

**重要设计决定要写进注释**：`ON CONFLICT DO NOTHING` + `RowsAffected()` 是幂等的实现（§4.2），而你**必须**在调用方处理 `IsNew == false` 分支（R15）。

**日志**：store 内部**不打印** SQL，而是通过 `slog` 在 `debug` 级别打印。方便的做法是给 `Store` 加一个 `log *slog.Logger` 字段，并在 `Open` 时传入。

```go
import (
    "context"
    "fmt"

// Provider 一个不发真实消息、只把内容打印出来的假平台实现。
// 用途：① 单测；② config 里 provider: mock 时做本地调试（§5.9 的 D2 决策）
type Provider struct {
    mu     sync.Mutex
    sent   []platform.OutgoingMessage   // 单测里可以断言「发了几段、内容是什么」
    events chan platform.IncomingMessage
    status platform.Status
}

func New() *Provider {
    return &Provider{
        events: make(chan platform.IncomingMessage, 64),
        status: platform.StatusDisconnected,
    }
}

func (p *Provider) Name() string { return "mock" }

func (p *Provider) Start(ctx context.Context) error {
    p.mu.Lock()
    p.status = platform.StatusConnected
    p.mu.Unlock()
    return nil
}

func (p *Provider) Stop(ctx context.Context) error {
    p.mu.Lock()
    defer p.mu.Unlock()
    if p.status == platform.StatusDisconnected {
        return nil
    }
    p.status = platform.StatusDisconnected
    close(p.events)          // 只有「生产者」关闭 channel
    return nil
}

func (p *Provider) Status() platform.Status {
    p.mu.Lock()
    defer p.mu.Unlock()
    return p.status
}

func (p *Provider) Send(ctx context.Context, msg platform.OutgoingMessage) (platform.SentMessage, error) {
    p.mu.Lock()
    defer p.mu.Unlock()
    p.sent = append(p.sent, msg)
    fmt.Printf("[mock] → %s/%s: %s\n", msg.Conv.Scene, msg.Conv.SceneID, msg.Text)
    return platform.SentMessage{MsgID: fmt.Sprintf("mock-%d", len(p.sent))}, nil
}

func (p *Provider) Events() <-chan platform.IncomingMessage { return p.events }

// ---- 测试辅助 ----

// Inject 注入一条入站事件（模拟用户发消息）。单测与 /admin/debug/inject 都用它。
func (p *Provider) Inject(ctx context.Context, msg platform.IncomingMessage) error {
    select {
    case p.events <- msg:
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

// Sent 返回已发送的消息快照（单测断言用）
func (p *Provider) Sent() []platform.OutgoingMessage {
    p.mu.Lock()
    defer p.mu.Unlock()
    return append([]platform.OutgoingMessage(nil), p.sent...)  // 复制一份，避免共享底层数组
}
```

**这段代码在教你四件事**

| 点 | 说明 |
|----|------|
| 生产者关闭 channel | `Stop()` 里 `close(p.events)`，且加了「只关一次」的保护 |
| 向 channel 发送必须带 `ctx.Done()` | `Inject` 里的 `select`，否则消费者退出后这里永久阻塞 |
| `sync.Mutex` 保护切片 | `Send` 会被多个会话并发调用（`chat` 可能同时给不同会话发消息） |
| 返回快照要复制 | `append([]T(nil), src...)` 是复制 slice 的惯用法；直接返回 `p.sent` 会让调用方和内部共享底层数组 |

```go
// retry.go
func Do[T any](ctx context.Context, attempts int, log *slog.Logger, fn func(ctx context.Context) (T, error)) (T, error) {
    var zero T
    backoff := []time.Duration{time.Second, 2 * time.Second, 4 * time.Second}
    var lastErr error
    for i := 0; i < attempts; i++ {
        if i > 0 {
            d := backoff[min(i-1, len(backoff)-1)]
            select {
            case <-time.After(d):
            case <-ctx.Done():
                return zero, ctx.Err()      // 关闭服务时立刻返回，不要傻等
            }
            log.Warn("模型调用重试", "attempt", i+1)
        }
        v, err := fn(ctx)
        if err == nil {
            return v, nil
        }
        lastErr = err
        if !errors.Is(err, llm.ErrRetryable) && !errors.Is(err, llm.ErrRateLimited) {
            return zero, err                 // 不可重试：立刻返回
        }
    }
    return zero, fmt.Errorf("重试 %d 次后仍失败: %w", attempts, lastErr)
}
```

> 用泛型 `Do[T]` 是为了让「重试」这段逻辑只写一次，且能在单测里独立验证（注入一个固定失败的 `fn`，断言调用次数与耗时）。如果你觉得泛型太难，V1 也可以先针对 `llm.Response` 写一个非泛型版本 —— **能跑起来比优雅重要**。

### 10.3.1 `split.go`（纯函数，最适合练手）

```go
package chat

import (
    "strings"
    "unicode/utf8"
)

const truncateSuffix = "…（内容过长已截断）"

// Split 把长回复切成至多 maxSegments 段，每段不超过 maxChars 个字符。
//
// ⚠️ 必须用「字符数」而不是「字节数」：Go 里 len("中文") == 6，不是 2。
func Split(text string, maxChars, maxSegments int, splitOn string) []string {
    text = strings.TrimSpace(text)
    if text == "" {
        return nil
    }
    if maxChars <= 0 {
        maxChars = 1500
    }
    if maxSegments <= 0 {
        maxSegments = 3
    }
    if utf8.RuneCountInString(text) <= maxChars {
        return []string{text}
    }

    // ① 先按 splitOn（通常是 "\n\n"）分块，再贪心装段
    var segs []string
    var buf strings.Builder
    for _, block := range strings.Split(text, splitOn) {
        block = strings.TrimSpace(block)
        if block == "" {
            continue
        }
        // 单块就超长 → 先硬切
        for utf8.RuneCountInString(block) > maxChars {
            head, tail := hardSplit(block, maxChars)
            if buf.Len() > 0 {
                segs = append(segs, buf.String())
                buf.Reset()
            }
            segs = append(segs, head)
            block = tail
        }
        candidate := block
        if buf.Len() > 0 {
            candidate = buf.String() + splitOn + block
        }
        if utf8.RuneCountInString(candidate) > maxChars {
            segs = append(segs, buf.String())
            buf.Reset()
            buf.WriteString(block)
        } else {
            buf.Reset()
            buf.WriteString(candidate)
        }
    }
    if buf.Len() > 0 {
        segs = append(segs, buf.String())
    }

    // ② 段数超限 → 把溢出的全部并进最后一段
    if len(segs) > maxSegments {
        last := strings.Join(segs[maxSegments-1:], splitOn)
        segs = append(segs[:maxSegments-1], last)
    }

    // ③ 最后一段仍超长 → 截断
    if last := segs[len(segs)-1]; utf8.RuneCountInString(last) > maxChars {
        segs[len(segs)-1] = truncateRunes(last, maxChars-len([]rune(truncateSuffix))) + truncateSuffix
    }
    return segs
}

// hardSplit 在第 n 个字符处切开（按 rune 切，不能切断多字节字符）
func hardSplit(s string, n int) (head, tail string) {
    rs := []rune(s)
    if len(rs) <= n {
        return s, ""
    }
    return string(rs[:n]), string(rs[n:])
}

func truncateRunes(s string, n int) string {
    if n <= 0 {
        return ""
    }
    rs := []rune(s)
    if len(rs) <= n {
        return s
    }
    return string(rs[:n])
}
```

**这段代码的教学点**

| 点 | 说明 |
|----|------|
| `utf8.RuneCountInString` / `[]rune` | Go 的字符串是**字节**序列。中文一个字 3 字节，用 `len()` 会把配额算错 3 倍 |
| `strings.Builder` | 高频拼接用它而不是 `+=`（`+=` 每次都重新分配） |
| 「贪心装段」的循环 | 先按 `splitOn` 切块，再往当前段里塞，塞不下就换段 —— 这是最不容易出 bug 的切分方式 |
| 三层降级 | ① 块内硬切 → ② 段数合并 → ③ 截断。**顺序不能换**，否则会先把内容合并又发现超长 |

**单测要点**（表驱动 + 边界）

```go
func TestSplit(t *testing.T) {
    tests := []struct{ name, in string; maxC, maxS int; wantSegs int; wantLastSuffix bool }{
        {"短文本不切", "你好", 100, 3, 1, false},

            for i, s := range segs {

                    t.Errorf("第 %d 段 %d 字符，超过上限 %d", i, utf8.RuneCountInString(s), tt.maxC)
                }
            }
        })
    }
}
```

### 10.3.2 `context.go`（上下文窗口）

```go

            case "user":
```

**V1 末 / V2 要补的降级逻辑**（R14）：如果 `ErrContextTooLong`，把 `turns` 减半重试，直到 0 轮：

### 10.3.3 `dedup.go`（快路径 LRU）

```go
// Dedup 内存去重快路径。真相在 turns 表的 UNIQUE 约束（§4.2），
// 这里只是为了避免重复走 SQL。所以它「失效」（如进程重启）是安全的。
type Dedup struct {
    mu   sync.Mutex
    seen map[string]time.Time
    ttl  time.Duration
}

func NewDedup(ttl time.Duration) *Dedup {
    return &Dedup{seen: make(map[string]time.Time), ttl: ttl}
}

// Seen 返回 true 表示近期已见过。会顺手清理过期项。
func (d *Dedup) Seen(key string) bool {
    d.mu.Lock()
    defer d.mu.Unlock()
    now := time.Now()
    for k, t := range d.seen {          // ⚠️ 遍历时删除 map 元素在 Go 里是合法的
        if now.Sub(t) > d.ttl {
            delete(d.seen, k)
        }
    }
    if _, ok := d.seen[key]; ok {
        return true
    }
    d.seen[key] = now
    return false
}
```

> **`map` 的并发读写会直接崩进程且无法 recover**（§9.2 #11）。所以这里**必须**有 `sync.Mutex`。如果去重表很大（几十万条），清理策略改成「定时 goroutine 清理」而不是每次遍历。

### 10.3.4 `outbound.go`（分段 + 发送）——**§8.7 的「缝 1」**

```go
// Outbound 负责「把一段文本变成 N 条平台消息」。V2.5（作业列表）与 V3（定时任务）会复用它。
type Outbound struct {
    provider platform.Provider
    events   EventSink
    log      *slog.Logger
}

type SendResult struct {
    Segments       int
    Sent           int
    Err            error
    QuotaExhausted bool
}

// SendText 发送文本；reply 为 nil 表示主动消息（V3 定时任务用）。
func (o *Outbound) SendText(ctx context.Context, conv platform.ConversationKey,
    reply *platform.ReplyRef, text string, cfg config.ChatConfig) SendResult {

    segs := Split(text, cfg.SegmentMaxChars, cfg.MaxReplySegments, cfg.SegmentSplitOn)
    res := SendResult{Segments: len(segs)}

    for i, seg := range segs {
        if i > 0 {
            // 打字延迟：让长回复更像人在打字（可配置；被动窗口是 60min，不用担心）
            select {
            case <-time.After(time.Duration(300+utf8.RuneCountInString(seg)) * time.Millisecond):
            case <-ctx.Done():
                res.Err = ctx.Err()
                return res
            }
        }

        sent, err := o.provider.Send(ctx, platform.OutgoingMessage{
            Conv: conv, Reply: reply, Kind: platform.OutText, Text: seg,
        })
        if err != nil {
            res.Err = err
            o.events.Append(ctx, Event{
                Kind: "outbound_error", Level: "error",
                Message: fmt.Sprintf("第 %d/%d 段发送失败", i+1, len(segs)),
                Payload: map[string]any{"error": err.Error()},
            })
            if errors.Is(err, platform.ErrReplyQuotaExhausted) {
                res.QuotaExhausted = true
                break           // 次数已耗尽，继续发只会全失败（R1）
            }
            if res.Sent == 0 {
                return res      // 第一段就失败 → 整轮算 failed
            }
            continue            // 后续段失败 → 保留已发送内容，继续尝试（R16）
        }
        res.Sent++
        o.events.Append(ctx, Event{
            Kind: "outbound", Level: "info",
            Message: fmt.Sprintf("第 %d/%d 段已发送 (%d 字符)", i+1, len(segs), utf8.RuneCountInString(seg)),
            Payload: map[string]any{"msg_id": sent.MsgID, "msg_seq": sent.Seq},
        })
    }
    return res
}
```

**判轮成败的规则（R16）**：`Sent == 0` → `failed`；`Sent > 0` → 轮记为 `ok`（用户已经看到部分内容，模型下一轮也该知道它说过什么）。这个判断放在 `service.go` 里做，`Outbound` 只回报事实。

### 10.3.6 `dispatcher.go`（分片串行队列）——R3 的对策

```go
// Dispatcher 按会话分片的串行队列。
//
// 同一个 ConversationKey 一定落到同一个 shard，所以同会话串行；
// 不同会话用不同 shard，所以仍然并行。
type Dispatcher struct {
    shards []chan platform.IncomingMessage
    handle func(ctx context.Context, msg platform.IncomingMessage)
    wg     sync.WaitGroup
}

func NewDispatcher(shards, queueSize int, handle func(context.Context, platform.IncomingMessage)) *Dispatcher {
    d := &Dispatcher{handle: handle}
    d.shards = make([]chan platform.IncomingMessage, shards)
    for i := range d.shards {
        d.shards[i] = make(chan platform.IncomingMessage, queueSize)
    }
    return d
}

// Run 启动 worker 并阻塞直到 ctx 取消。
func (d *Dispatcher) Run(ctx context.Context) {
    for i := range d.shards {
        d.wg.Add(1)
        go func(ch <-chan platform.IncomingMessage) {
            defer d.wg.Done()
            for {
                select {
                case <-ctx.Done():
                    return
                case msg, ok := <-ch:
                    if !ok {
                        return
                    }
                    d.handle(ctx, msg)
                }
            }
        }(d.shards[i])
    }
    d.wg.Wait()
}

// Submit 入队。队列满时阻塞（天然背压），但响应 ctx 取消。
func (d *Dispatcher) Submit(ctx context.Context, msg platform.IncomingMessage) error {
    ch := d.shards[shardOf(msg.Conv)]
    select {
    case ch <- msg:
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

// shardOf 用 FNV 哈希把会话 key 稳定映射到分片。
func shardOf(k platform.ConversationKey) int {
    h := fnv.New32a()
    _, _ = h.Write([]byte(k.AppID + "|" + string(k.Scene) + "|" + k.SceneID))
    return int(h.Sum32()) % shardCount   // shardCount 作为常量或字段
}
```

**这段代码的教学点**

| 点 | 说明 |
|----|------|
| 不关闭 shard channel | 关闭 channel 是「生产者」的责任，而 shard 的生产者是 `Submit`（可能有多个 goroutine 调用）。**用 `ctx.Done()` 退出而不是 close**，避免「向已关闭 channel 发送」的 panic |
| `select` 双分支 | 每个发送/接收都配 `ctx.Done()`，是 Go 里防 goroutine 泄漏的标准姿势 |
| `sync.WaitGroup` | `Run` 要等所有 worker 退出才返回，否则优雅关闭时会漏 |
| 队列满时阻塞 | 这是**背压**而不是 bug：一个人连发 100 条时应该排队而不是无限制起 goroutine |

**分片数怎么定**：V1 建议 `shards = 8`、`queueSize = 16`。分片数不是越大越好（每个 shard 一个常驻 goroutine）。

### 10.3.7 `service.go`（生命周期与单条消息编排）

```go
type Service struct {
    provider   platform.Provider
    store      Store
    pipeline   *Pipeline        // 持有 []Step
    outbound   *Outbound
    dedup      *Dedup
    dispatcher *Dispatcher
    cfg        func() config.ChatConfig
    loc        *time.Location
    log        *slog.Logger
    events     EventSink
}

func New(deps Deps) *Service {
    s := &Service{ /* ... */ }
    s.dispatcher = NewDispatcher(8, 16, s.handleOne)
    return s
}

// Run 消费事件流，直到 ctx 取消或 provider 关闭。
func (s *Service) Run(ctx context.Context) error {
    go func() {
        for {
            select {
            case <-ctx.Done():
                return
            case msg, ok := <-s.provider.Events():
                if !ok {
                    return          // provider 关闭了 Events 通道
                }
                if err := s.dispatcher.Submit(ctx, msg); err != nil {
                    s.log.Warn("入队失败", "error", err)
                }
            }
        }
    }()
    s.dispatcher.Run(ctx)        // 阻塞直到 ctx 取消
    return nil
}

// handleOne 处理一条入站消息（在 shard worker 里执行，同会话天然串行）。
func (s *Service) handleOne(ctx context.Context, msg platform.IncomingMessage) {
    cfg := s.cfg()                                    // 每次读取最新配置（热重载生效）
    log := s.log.With("trace_id", traceIDOf(msg))
    ctx = context.WithValue(ctx, ctxKeyTrace, traceIDOf(msg))

    s.events.Append(ctx, Event{Kind: "inbound", Message: "收到消息",
        Payload: map[string]any{"msg_id": msg.MsgID, "scene": msg.Conv.Scene,
            "chars": utf8.RuneCountInString(msg.Text), "has_attachment": msg.HasAttachment}})

    // ① 快路径去重（真相在 DB 的 UNIQUE 约束）
    if s.dedup.Seen(keyOf(msg)) {
        s.events.Append(ctx, Event{Kind: "inbound_duplicate", Message: "重复推送，跳过"})
        return
    }

    // ② 会话
    convID, err := s.store.GetOrCreateConversation(ctx, msg.Conv, msg.Sender)
    if err != nil { log.Error("会话读写失败", "error", err); return }

    // ③ 非文本消息（§1.3）：不调模型，记 filtered 轮
    if msg.Text == "" || (msg.HasAttachment && msg.Text == "") {
        tn, _ := s.store.BeginTurn(ctx, TurnParams{ConvID: convID, MsgID: msg.MsgID,
            Sender: msg.Sender, UserText: "", TraceID: traceIDOf(msg), StartedAt: msg.Timestamp})
        if tn.IsNew {
            _ = s.store.FinishTurn(ctx, tn.ID, StatusFiltered, "", llm.Usage{})
        }
        s.events.Append(ctx, Event{Kind: "inbound_filtered", Message: "非文本消息，未调用模型"})
        _, _ = s.outbound.SendText(ctx, msg.Conv, platform.NewReplyRef(msg.MsgID, msg.EventID),
            "目前只支持文字消息哦～", cfg)
        return
    }

    // ④ 建轮（幂等）
    tn, err := s.store.BeginTurn(ctx, TurnParams{ConvID: convID, MsgID: msg.MsgID,
        Sender: msg.Sender, UserText: msg.Text, TraceID: traceIDOf(msg), StartedAt: msg.Timestamp})
    if err != nil { log.Error("建轮失败", "error", err); return }

    if !tn.IsNew {
        // R15：区分「真重复」与「崩溃遗留」
        if !s.shouldReclaim(ctx, tn.StartedAt) {
            log.Info("重复推送，跳过", "turn", tn.ID, "status", tn.Status)
            return
        }
        log.Warn("接管未完成的轮，重试", "turn", tn.ID)
    }

    reply := platform.NewReplyRef(msg.MsgID, msg.EventID)   // ⚠️ 被动回复凭据

    t := &Turn{In: msg, Reply: reply, Trace: traceIDOf(msg), ConvID: convID,
        TurnRef: tn, Cfg: cfg, Log: log}

    // ⑤ 走步骤链
    _, err = s.pipeline.Run(ctx, t)
    if err != nil {
        _ = s.store.FinishTurn(ctx, tn.ID, StatusFailed, "", llm.Usage{})
        // 面向用户的兜底文案（10.4 的 errorCopy）
        _, _ = s.outbound.SendText(ctx, msg.Conv, reply, errorCopy(err), cfg)
        return
    }

    // ⑥ 出站
    res := s.outbound.SendText(ctx, msg.Conv, reply, t.ReplyText, cfg)

    // ⑦ 定轮状态（R16）
    status := StatusOK
    if res.Sent == 0 {
        status = StatusFailed
    }
    _ = s.store.FinishTurn(ctx, tn.ID, status, t.ReplyText, llm.Usage{})
}
```

**这段代码里的每个 `⚠️` 都对应一条风险**。建议你写的时候对照 `06-风险与遗漏点清单.md` 逐条打勾。

**`sentinel 关键点`**：`s.cfg()` 每次调用取最新配置 → 这就是「热重载生效」的实现，无需重建 `Service`（§3.4.1）。

```go
// errorCopy 把内部错误映射成用户可读文案。
```

```go
        return fmt.Errorf("数据库迁移失败: %w", err)
    }
    ver, _ := st.MigrationVersion(ctx)
    log.Info("迁移完成", "user_version", ver)

    if migrateStatusOnly {
        fmt.Printf("user_version = %d\n", ver)
        return nil
    }

    if stale, _ := st.StaleTurnsAll(ctx); len(stale) > 0 {
        log.Warn("上次有未完成的轮次", "count", len(stale))   // R15 的输入
    }

    // ── 5. 适配器（工厂：唯一的 switch，见 §2.4）
    provider, err := platform.New(cfg.Bot, log)     // platform/factory.go
    if err != nil {
        return err
    }
    llmClient, err := llm.New(cfg.LLM, log)         // llm/factory.go
    if err != nil {
        return err
    }

    // ── 6. 时区（一次性加载，往下传）
    loc, err := time.LoadLocation(cfg.Chat.Timezone)
    if err != nil {
        return fmt.Errorf("加载时区 %q: %w", cfg.Chat.Timezone, err)
    }

    // ── 7. 业务
    chatSvc := chat.New(chat.Deps{
        Provider: provider, LLM: llmClient, Store: st,
        Cfg: func() config.ChatConfig { return holder.Load().Chat },
        Loc: loc, Log: log, Events: st,
    })

    adminSrv := admin.New(admin.Deps{
        Cfg: func() config.Config { return *holder.Load() },
        Store: st, Chat: chatSvc, Bot: provider, Log: log, Reload: ..., Restart: ...,
    })

    // ── 8. 启动
    if err := provider.Start(ctx); err != nil {
        return fmt.Errorf("平台连接失败: %w", err)
    }
    go func() {
        if err := adminSrv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            log.Error("admin 服务异常", "error", err)
            cancel()            // 让主流程退出
        }
    }()

    log.Info("就绪", "listen", cfg.Server.Listen, "provider", provider.Name(), "llm", llmClient.Name())

    // ── 9. 跑业务（阻塞）
    chatSvc.Run(ctx)

    // ── 10. 优雅关闭（顺序见 §5.8）
    log.Info("开始关闭")
    shutCtx, shutCancel := context.WithTimeout(context.Background(),
        time.Duration(cfg.Chat.ShutdownGraceSec)*time.Second)
    defer shutCancel()

    if err := provider.Stop(shutCtx); err != nil {
        log.Warn("断开平台出错", "error", err)     // 15s 超时后不阻塞退出
    }
    if err := adminSrv.Shutdown(shutCtx); err != nil {
        log.Warn("关闭 admin 出错", "error", err)
    }
    log.Info("已退出")
    return nil
}
```

**这段代码在教你 Go 的「组装」范式**

| 点 | 说明 |
|----|------|
| 全是 `new` 集中在 `run()` | 这就是「组合根」。没有全局单例，没有 `init()` 魔法 |
| `signal.NotifyContext` | 一行把 SIGINT/SIGTERM 变成 `ctx.Done()`，比手写信号 channel 干净 |
| `defer closeLog()` / `defer st.Close()` | 关闭顺序是 LIFO：`st.Close()` 先于 `closeLog()`。而优雅关闭（provider.Stop）走的是**显式顺序**，因为要受超时约束 |
| `holder.Load()` 包成函数往下传 | 热重载能生效的关键（§3.4.1） |
| 返回 error 而不是 panic | 启动失败时打印一行清晰的错误 + 退出码 1，方便 supervisor 判断 |

### 10.7.2 `replyseq.go`：msg_seq 原子递增

```go
// seqTracker 为每个 msg_id 维护一个递增序号。
// 平台按 (msg_id, msg_seq) 去重，重复序号会被静默丢弃（40054005）。
type seqTracker struct {
    mu   sync.Mutex
    seqs map[string]uint32
}

func newSeqTracker() *seqTracker { return &seqTracker{seqs: make(map[string]uint32)} }

// Next 返回下一个序号。同一个 msg_id 第一次得到 1，然后 2、3…
func (t *seqTracker) Next(msgID string) uint32 {
    t.mu.Lock()
    defer t.mu.Unlock()
    t.seqs[msgID]++
    return t.seqs[msgID]
}

// Forget 一次入站消息处理完后清理，防止 map 无限增长。
func (t *seqTracker) Forget(msgID string) {
    t.mu.Lock()
    defer t.mu.Unlock()
    delete(t.seqs, msgID)
}
```

> 也可以把这个计数器放进 `platform.ReplyRef` 内部（§3.1.1 的设计）。**两种都可以**：放 `ReplyRef` 里更内聚，但需要 `atomic.Uint32`；放适配器里则需要 map + 锁。**建议放 `ReplyRef`**，因为「一次入站消息 → 一个 ReplyRef → 序号序列」是天然绑定的一对，且不用清理 map（`ReplyRef` 随 `Turn` 一起被 GC）。适配器里就只调用 `msg.Reply.NextSeq()`。

### 10.7.3 `outbound.go`：内部消息 → botgo 发送

```go
func (p *Provider) Send(ctx context.Context, msg platform.OutgoingMessage) (platform.SentMessage, error) {
    if msg.Reply == nil {
        // 主动消息（V3 定时任务用）。V1 几乎不会走这里。
        p.log.Warn("发送主动消息（受频控约束）", "scene", msg.Conv.Scene)
    }

    switch msg.Conv.Scene {
    case platform.SceneC2C:
        return p.sendC2C(ctx, msg)
    case platform.SceneGroup:
        return p.sendGroup(ctx, msg)      // V1 不实现，返回 ErrUnsupportedScene
    default:
        return platform.SentMessage{}, fmt.Errorf("qqbot: 未知场景 %q", msg.Conv.Scene)
    }
}

func (p *Provider) sendC2C(ctx context.Context, msg platform.OutgoingMessage) (platform.SentMessage, error) {
    mc := &dto.MessageToCreate{Content: msg.Text}
    if msg.Reply != nil {
        mc.MsgID = msg.Reply.MsgID
        mc.MsgSeq = msg.Reply.NextSeq()        // ⚠️ 必须递增；SDK 不会帮你做
    }
    if msg.Kind == platform.OutTyping {
        mc.MsgType = 6                          // 「输入中」（待实测 T3：是否消耗次数）
    }

    sent, err := p.api.PostC2CMessage(ctx, msg.Conv.SceneID, mc)
    if err != nil {
        if isQuotaExhausted(err) {              // 待实测 T4：确认错误码
            return platform.SentMessage{}, fmt.Errorf("%w: %v", platform.ErrReplyQuotaExhausted, err)
        }
        return platform.SentMessage{}, fmt.Errorf("qqbot: 发送单聊消息: %w", err)
    }
    return platform.SentMessage{MsgID: sent.ID, Seq: mc.MsgSeq}, nil
}
```

### 10.7.5 重连：**只在 `Start` 注册一次 handler**（R12 症状 B）

```go
func (p *Provider) Start(ctx context.Context) error {
    // token 自动刷新协程
    if err := token.StartRefreshAccessToken(ctx, p.tokenSource); err != nil {
        return fmt.Errorf("qqbot: 启动 token 刷新: %w", err)
    }

    // ⚠️ 只注册一次！放在重连回调里会导致「一条消息被处理两次」
    if err := event.RegisterHandlers(p.onC2CMessage); err != nil {
        return fmt.Errorf("qqbot: 注册事件: %w", err)
    }

    go p.runLoop(ctx)      // 内部负责 ws 建立与重连，但不再注册 handler
    return nil
}

func (p *Provider) onC2CMessage(_ *dto.WSPayload, data *dto.WSC2CMessageData) error {
    msg := translateC2C(p.cfg.AppID, data)
    select {
    case p.events <- msg:
        return nil
    case <-p.done:                  // 服务已停止
        return nil
    }
}
```

**验证方式**：断网 10 秒再恢复，发一条消息，`GET /admin/logs?kind=inbound` 只应出现一条。

```go
func TestChat_EndToEnd(t *testing.T) {

    prov := mock.New()

    cfg := config.ChatConfig{ContextTurns: 10, MaxReplySegments: 3, SegmentMaxChars: 100}

        Cfg: func() config.ChatConfig { return cfg }, Loc: time.UTC,
        Log: discardLogger(), Events: st})

    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()
    if err := prov.Start(ctx); err != nil { t.Fatal(err) }
    go svc.Run(ctx)

    conv := platform.ConversationKey{AppID: "app1", Scene: platform.SceneC2C, SceneID: "u1"}
    if err := prov.Inject(ctx, platform.IncomingMessage{
        MsgID: "m1", Conv: conv, Sender: platform.Sender{OpenID: "u1"},
        Text: "你好", Timestamp: time.Now(),
    }); err != nil { t.Fatal(err) }

    // 轮询等待回复（不要用 sleep 猜时间）
    waitFor(t, 2*time.Second, func() bool { return len(prov.Sent()) > 0 })

    if got := prov.Sent()[0].Text; got != "你好，我是测试机器人。" {
        t.Errorf("回复 = %q", got)
    }
    // 断言模型看到的上下文
    if len(fakeLLM.Calls) != 1 {
        t.Fatalf("模型被调用 %d 次，want 1", len(fakeLLM.Calls))
    }
    if fakeLLM.Calls[0].System != "" && len(fakeLLM.Calls[0].Messages) != 1 {
        t.Errorf("首次对话的上下文应只有当前消息，实际 %d 条", len(fakeLLM.Calls[0].Messages))
    }
}

// waitFor 是测试里等待异步结果的通用小工具。
func waitFor(t *testing.T, d time.Duration, cond func() bool) {
    t.Helper()
    deadline := time.Now().Add(d)
    for time.Now().Before(deadline) {
        if cond() { return }
        time.Sleep(10 * time.Millisecond)
    }
    t.Fatal("等待超时")
}
```

**这个测试就是 §1.5 「质量验收」的核心条目**：不连 QQ、不调模型，全链路可验证。

## 10.9 常见编译 / 运行错误速查

| 报错 | 原因 | 解法 |
|------|------|------|
| `undefined: xxx` | 首字母小写、或跨包引用小写标识符 | 导出标识符首字母大写（§9.2 #1） |
| `import cycle not allowed` | 包互相 import（典型：`config` → `llm` → `config`） | 接口定义在使用方；把共享类型抽到更底层的包（§2.1） |
| `declared and not used` | Go 不允许未使用的局部变量 | 用 `_ = x` 或删掉；**不要**用 `_ = err` 掩盖错误 |
| `missing return` | 分支没覆盖所有路径 | 补 `return`；或用命名返回值 |
| `cannot use x (type T) as type S` | 没做类型转换 | 显式转换 `S(x)`，或检查接口方法集是否匹配 |
| `method has pointer receiver` | 值类型调用指针接收者方法（如 `mock.Provider{}` 而非 `&mock.Provider{}`） | 用指针 `&T{}`（§9.2 #7） |
| `concurrent map read and map write` | map 无锁并发访问 | 加 `sync.Mutex`（§9.2 #11） |
| `sql: database is locked` | 并发写 SQLite | DSN 里加 `busy_timeout`；`SetMaxOpenConns(1)`（§4.6） |
| `no such table: turns` | 忘了调 `Migrate`，或迁移文件没被 embed | 启动时先 Migrate；检查 `//go:embed migrations/*.sql` 路径 |
| `context deadline exceeded` | 超时；或 `ctx` 被上游取消 | 检查是否到处新建 `context.Background()`（§9.2 #13） |
| `write ...: file already closed` | `defer` 顺序错，或重复 Close | 检查关闭函数是否被 defer 两次 |
| `panic: assignment to entry in nil map` | 只 `var m map[K]V` 没 make | `m := make(map[K]V)` |
| `index out of range` | 空 slice 取 `[0]` | 先判 `len(x) > 0` |
| `-race` 报 race | 真有数据竞争 | 看报错里的两个 goroutine 栈，通常是共享的 slice/map |

**两个习惯能挡掉一半问题**

1. **每次提交前跑**：`gofmt -l -w . && go vet ./... && go test ./... -race`
2. **`go vet` 的告警当错误处理**，尤其 `copylocks`（复制了含 mutex 的结构体）和 `loopclosure`
