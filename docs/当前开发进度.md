## 一、这个项目是什么

一个**个人学习性质的 Go 项目**：QQ 官方机器人 + AI 对话服务，从 TypeScript 版 `napcat-platform` 改造而来。

| | |
|---|---|
| **首要目的** | **学会 Go**（次要目的才是「跑起来」） |
| 语言 / 版本 | Go 1.23.6 |
| QQ 侧 SDK | `github.com/tencent-connect/botgo` v0.2.1（官方 WS 收事件 + v2 单聊接口发送） |
| LLM 侧 | 标准库 `net/http` 直连（不引厂商 SDK），V1 计划支持 OpenAI Chat / OpenAI Responses / Anthropic 三种协议 |
| 存储 | 计划用 `modernc.org/sqlite`（纯 Go，免 CGO）+ `log/slog` 写文件日志 |
| 依赖白名单 | 只允许 `botgo`、`modernc.org/sqlite`、`yaml.v3`、`lumberjack.v2`，其余一律标准库 |
| 项目约定 | 见仓库根的 [`AGENTS.md`](../AGENTS.md)（其中 §5 是「约定速查表」） |

**它现在能做什么**：连上 QQ 官方机器人 → 收到别人私聊的文本消息 → 回一句「你说的是：xxx」。

**它现在还不会做什么**（别误解）：

- ❌ **不会调用大模型**。`internal/llm` 目前只有接口 + 假实现，三个真实协议适配器还没写。
  所以现在是**复读机**，不是 AI 机器人。
- ❌ 没有数据库、没有 HTTP 管理接口、没有命令（`/help` 之类）、不支持群聊。
- ❌ **一个单元测试都没有**（`go test ./...` 会说 `no test files`）。

## 二、三分钟跑起来

### 2.1 前置检查

```bash
go version          # 需要 >= 1.22（本仓库 go.mod 写的是 1.23.6）
```

如果 `go` 命令不存在，先装 Go：<https://go.dev/dl/>

### 2.2 拿代码 + 装依赖

```bash
git clone git@github.com:hui0882/QQ-bot-Go-.git
cd QQ-bot-Go-
go mod tidy         # 建议先跑一次：当前 go.mod 里的依赖被标成了 // indirect
go build ./...      # 应该没有任何输出（无输出 = 成功）
```

### 2.3 配置：只需要填一个文件

```bash
cp config.yaml.example config.yaml
```

然后编辑 `config.yaml`，**只改这几个字段**：

| 字段 | 填什么 | 注意 |
|------|--------|------|
| `bot.qqbot.app_id` | QQ 开放平台的 AppID | — |
| `bot.qqbot.app_secret` | 对应的 AppSecret | ⚠️ **绝不要提交**（`config.yaml` 已在 `.gitignore` 里） |
| `bot.qqbot.sandbox` | 沙箱机器人 `true` / 正式机器人 `false` | ⚠️ **必须和 AppID 配套**，填错会「连上了但收不到消息」 |
| `bot.provider` | 想连真 QQ 用 `qqbot`；只想本地跑用 `mock` | — |
| `llm.protocol` | 现在只能是 `fake` | 三个真实协议还没实现，写别的会启动失败（这是故意的） |

**这个项目不用环境变量**：所有配置只从 `config.yaml` 读（与设计文档 `03 §5.1` 的有意偏离，理由见 `AGENTS.md` §5）。
自检一下它确实不会被提交：

```bash
git check-ignore -v config.yaml     # 应输出 .gitignore:1:/config.yaml
```

### 2.4 第一次运行：先用 mock（不连 QQ、不联网）

`provider: mock` 时程序不连任何东西，只把「要发出去的消息」打印到 stdout。
把 `bot.provider` 改成 `mock` 后：

```bash
go run ./cmd/botd -config config.yaml
```

期望输出（然后按 `Ctrl-C` 退出）：

```
level=INFO msg=启动 service=botd version=dev config_path=config.yaml
level=INFO msg=适配器就绪 service=botd provider=mock llm=fake
level=INFO msg=开始关闭 service=botd
level=INFO msg=已退出 service=botd
```

同时日志会写一份到 `data/logs/botd.log`（目录自动创建）。

其他有用的：

```bash
go run ./cmd/botd -version          # 打印版本（botd dev (build unknown)）
go run ./cmd/botd -config /path/to/别的配置.yaml
```

### 2.5 连真 QQ

1. `bot.provider: qqbot`、`sandbox` 与你的 AppID 配套
2. `go run ./cmd/botd -config config.yaml`
3. 用**加了机器人好友/在沙箱白名单里的那个 QQ** 私聊机器人，发一句「你好」
4. 期望：
   - 日志出现 `收到消息 conv=<AppID>/c2c/<openid> msg_id=... text=你好`
   - QQ 里收到回复 **「你说的是：你好」**

> 收到消息 = 通信底座通了。**这里没有 AI**，它只是复读。

```

├── cmd/botd/main.go          ← 组合根。全项目唯一 new 对象的地方，读它就懂程序结构
├── internal/
│   ├── config/               ← 配置：加载 config.yaml + 校验。密钥只在这里进来
│   ├── logx/                 ← 日志：slog 配成「控制台 + 文件轮转」
│   ├── version/              ← 版本号（构建时注入）
│   ├── platform/             ← ① 通信底座（端口）
│   │   ├── scene.go          ←   会话身份：Scene / ConversationKey / Sender
│   │   ├── port.go           ←   Provider 接口 + 出入站消息类型（⚠️ 不许 import botgo）
│   │   ├── errors.go         ←   跨层哨兵错误（errors.Is 判断）
│   │   ├── factory/          ←   按配置选 mock 还是 qqbot（唯一的 switch）
│   │   └── provider/
│   │       ├── mock/         ←   假平台：不连 QQ，打印到 stdout
│   │       └── qqbot/        ←   真 QQ：provider(生命周期) / inbound(收) / outbound(发) / logger / errors
│   └── llm/                  ← ② 模型（端口，目前只有假实现）
│       ├── model.go          ←   与协议无关的中性消息模型
│       ├── port.go           ←   Client 接口
│       ├── errors.go         ←   可重试 / 鉴权 / 限流 / 上下文超长
│       ├── factory/          ←   按 protocol 选实现
│       └── provider/fake/    ←   假模型
└── docs/                     ← 文档（见 §九）
```

**数据流（现在的完整链路）**：

```
QQ 服务器 ──WS事件──▶ botgo 读循环 ──▶ qqbot.onC2CMessage ──▶ translateC2C（纯函数）
                                                                    │
                                                          Events() channel
                                                                    ▼
                                            main.echoLoop ──▶ Provider.Send ──▶ PostC2CMessage ──▶ QQ
```

等到 M3 做完，`echoLoop` 会被 `chat.Service` 取代，中间插入「去重 → 入队 → 拼上下文 → 调模型 → 分段」。

## 五、这个项目的 5 条硬规矩（初学者版）

完整版在 [`AGENTS.md`](../AGENTS.md) §5，这里只讲「为什么」：

| 规矩 | 大白话解释 |
|------|-----------|
| **端口 / 适配器** | 业务代码只认 `platform.Provider` 这个接口，不认 QQ。所以 `internal/platform/port.go` 里出现 `botgo` 字样就是设计事故——那样以后换平台（或写单测）都得动业务代码 |
| **依赖显式注入** | 没有全局单例、没有 `GetXxx()`。所有对象在 `main` 里 `new` 一次然后当参数传下去。这样单测可以塞 `mock`/`fake`，**不需要先启动整个项目** |
| **接口定义在使用方** | 接口写在「要用它」的包里（`platform` 定义 `Provider`），不写在实现方。这是 Go 与 Java 最大的习惯差异 |
| **错误要能判断** | 用 `fmt.Errorf("...: %w", err)` 包装 + 哨兵错误 + `errors.Is`。**绝不靠字符串匹配错误**，也别把平台原文直接抛给用户 |
| **配置只有一个来源** | 全从 `config.yaml` 读，不用环境变量、不做 `${VAR}` 展开。故障排查时只需看一个文件 |

另外两条风格约定：**注释写中文**，而且解释「**为什么**这么写」而不是「这行做了什么」；**日志用标准库 `log/slog`**，不要引 logrus/zap。

## 六、新手最容易踩的 9 个坑（都是本项目真实发生过的）

| # | 坑 | 症状 / 正确做法 |
|---|-----|----------------|
| 1 | `internal/` 放错位置 | 它必须在**仓库根**。放进 `cmd/server/internal/` 会导致 import 路径变成 `qq-bot/cmd/server/internal/...`，一堆 `is not in std` |
| 2 | 工厂和接口放同一个包 | `import cycle not allowed`。**Go 的环检测看的是「包」，父子目录照样成环**：`platform` 不能 import `provider/mock`（因为 `mock` 要 import `platform`）→ 工厂必须单独成包 `platform/factory/` |
| 3 | 接口方法名大小写 | 接口要 `Send`，你写了 `send`。Go 里这是**两个不同的方法**，报错形如 `have send(...) / want Send(...)` |
| 4 | `event.RegisterHandlers` 写成单数 | v0.2.1 里 `RegisterHandler` 是另一个 3 参数函数。注册业务 handler 用**复数**版，它返回 `dto.Intent` |
| 5 | `sessionManager.Start` 不套 `go` | 它内部是永不返回的事件循环 → 服务「启动成功但完全没反应」。必须 `go func(){ ... }()` |
| 6 | gofmt 老是重排你的注释 | Go 1.19 起，**注释里缩进的续行会被当成代码块**重排。别用缩进续行 |
| 7 | `sandbox` 与 AppID 不配套 | 连上了、日志正常，但**一条消息都收不到**。沙箱 AppID 必须 `sandbox: true` |
| 8 | 改了配置 schema 但没更新 `config.yaml` | 报 `bot.provider 不能为空`。旧版字段叫 `qq.app_id`，新 schema 是 `bot.qqbot.app_id` |
| 9 | 把 `config.yaml` 提交了 | 里面有 AppSecret。它已在 `.gitignore`，别用 `git add -f` 绕过；自检 `git check-ignore -v config.yaml` |

**遇到报错先做这两件事**：

```bash
go build ./... 2>&1 | head -20        # 编译错误
gofmt -l .                            # 列出格式不合规的文件（有输出就先 gofmt -w 它们）
```

> 小技巧：`go build ./...` **遇到第一个坏包就停，不报下游包的错**。想一次看全，逐包编译：
> `for d in $(find . -name "*.go" -exec dirname {} \; | sort -u); do go build "$d"; done`

## 七、怎么确认「我手上的代码是好的」

```bash
gofmt -l .                    # 期望：无输出
go build ./...                # 期望：无输出
go vet ./...                  # 期望：无输出
go test ./... -race           # 期望：全是 "no test files"（目前还没有测试）
go run ./cmd/botd -version    # 期望：botd dev (build unknown)
```

再加两条**设计约束的机械检查**（可以直接抄进将来的 Makefile）：

```bash
# ① 平台细节不许泄漏到端口层
grep -rn "botgo" internal/platform/*.go && echo "❌ 违规" || echo "✅ 端口层干净"

# ② 密钥/配置来源只有一处
grep -rn "LookupEnv\|Getenv" --include="*.go" . || echo "✅ 没有环境变量读取"
```

## 十、已知欠账（技术债清单）

诚实记录，免得后来者以为"这项目就这样"：

| # | 欠账 | 影响 | 怎么还 |
|---|------|------|--------|
| 1 | **零单元测试** | 改动无保护网；`go test` 等于没跑 | 按 §八 顺序 0，从 `split.go`、`translateC2C`、`ReplyRef` 这类纯函数开始 |
| 2 | `go.mod` 里依赖全标着 `// indirect` | 语义错（它们是直接依赖） | `go mod tidy`（本项目作者手动执行，agent 不代跑） |
| 3 | `mock.Inject` 有并发窗口 | 「检查 `closed`」和「发送」之间有竞态，可能 `send on closed channel` | 持锁发送或改用 `done` channel；用 `go test -race -count=200` 复现 |
| 4 | 没有 `Makefile` | 每次要手敲 `gofmt/vet/build/test` | 见 `03 §5.9` |
| 5 | 版本号永远是 `dev` | `-version` 看不出构建点 | `-ldflags "-X qq-bot/internal/version.GitHash=$(git rev-parse --short HEAD)"` |
| 6 | 没有 GitHub Actions | 推上去才知道编译坏没坏 | 加一个跑 `gofmt -l` + `go vet` + `go test -race` 的 workflow |
| 7 | `chat`/`store`/`admin`/真实 LLM 适配器未实现 | 现在是复读机，不是 AI 机器人 | 按 §八 顺序推进 |
| 8 | 根 `README.md` 内容极少 | 仓库首页没有介绍 | 已在同一次整理中补成导航页 |
