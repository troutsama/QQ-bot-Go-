## 三、三个容易迷路的地方

**① 章节号 ≠ 文档编号。**
文档集由早期 12 份合并成 8 份，**章节号沿用了原来的编号**（§1.x ~ §11.x），所以：

| 你看到的 | 它在哪份文件里 |
|---------|---------------|
| `§3.x`（接口定义） | `02-架构与接口.md` 第二部分 |
| `§4.x`、`§5.x`（表 / 运维） | `03-数据与运维.md` |
| `§6.x`、`R*`、`T*`、`D-*` | `04-风险与决策.md` |
| `§7.x` | `05-旧项目对照表.md` |
| `§8.x`（目录演进） | `01-总览.md` 第二部分 |
| `§9.x`、`§10.x`（编码指南） | `06-V1-编码指南.md` |
| `§11.x` | `08-V2V3-编码指南.md` |

看不到 `09-*.md`、`10-*.md`、`11-*.md` 是正常的——它们是合并前的旧文件名，内容已在 `06`、`08` 里。
迷失时查 [`design/README.md`](design/README.md) §三。

**② 设计文档里有几处已经和实践不一致**，以实践为准（都记录在案）：

| 位置 | 实践 |
|------|------|
| `02 §2.4` 说工厂放 `internal/platform/factory.go` | **编译不过**（import cycle）→ 实际放在 `internal/platform/factory/` 独立包 |
| `03 §5.1` 要求支持 `${VAR}` + 环境变量覆盖 | **有意不实现**：配置只从 `config.yaml` 读（见 `AGENTS.md` §5） |
| `06 §10.7` 的 botgo 示例 | 按 v0.2.1 的真实签名订正了 6 处（`SetLogger`、`RegisterHandlers`、`PostC2CMessage` 参数是 `dto.APIMessage` 等） |

**③ `learn/` 不在 `docs/` 下，而且不入库。**
它是"练习册参考答案"（含已落地部分的完整代码、为什么、陷阱、测试清单），
定位是**先自己写、卡住了再对照**，所以刻意用 `.gitignore` 排除，避免变成抄写材料。

## 四、文档维护约定

| 什么变了 | 要改哪些 |
|---------|---------|
| 新写完一个包 / 一个里程碑 | `当前开发进度.md` §三 进度表 + §十 欠账清单 + 附：变更记录 |
| 实践与设计文档冲突 | 先在 `当前开发进度.md` 或 `AGENTS.md` §5 记录「有意偏离」，再讨论谁该改 |
| 发现设计文档写错了 | 改设计文档本身，并在其「变更记录」里注明 |
| 目录改名 / 移动 | 全仓库 `grep -rn "旧路径"` 一次改干净，并检查设计文档内部的交叉引用 |
